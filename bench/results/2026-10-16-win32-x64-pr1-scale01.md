## Deterministic work and compatibility checks

Before implementation, the instrumented original code failed six resource
assertions. After implementation, all ten native tests pass:

- Excluded child names trigger no child metadata calls or subtree enumeration;
  an explicitly selected hidden root remains searchable.
- Known oversize handles read zero body bytes; growth after the handle precheck
  reads at most 32 MiB + 1. Empty/exact-limit files are accepted.
- Summary constructs zero content items and summary/count retain no hit-position
  vectors. Same-line repeats still count as one matching line.
- A 300-hit file with offset 128 / limit 2 constructs two content items, retaining
  matched=300, total=300, omitted=170 and nextOffset=130. Multi-file pages and
  files_with_matches preserve the original per-file stop boundary.
- Two glob patterns parse twice per request and split each candidate path once;
  case, byte-oriented ?, literal brackets/braces, negative priority and explicit
  file-target behavior are preserved.
- A 1 MiB hex input with a 32-byte requested window reads 32 bytes. EOF/large
  offsets work; short reads and observed size changes report REVISION_CONFLICT.
- Strict full-file UTF-8 validation, BOM, NUL, CRLF and multibyte boundaries retain
  their original behavior. Metrics are test-only and absent from the release.
